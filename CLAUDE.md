# pulse3d — 3D-сцена квартиры для планирования ремонта

Статическая страничка: three.js-сцена квартиры (10 помещений по плану БТИ).
Хостится на GitHub Pages: https://samush.github.io/pulse3d/ — деплой
автоматический с ветки `main`, поэтому ничего публиковать отдельно не нужно,
но в `main` должно попадать только проверенное.

## Рабочий процесс

- Коммитить и пушить сразу в `main`, без PR (репозиторием пользуется один человек).
- Задачи в чате ставятся по номерам помещений («в комнате 3…») — эталон
  номеров, площадей и размеров: `APARTMENT.md`.
- Перед пушем прогнать smoke-тест: `node tools/check.js`
  (один раз на окружение: `npm i && npx playwright install chromium` — версия playwright закреплена в `package.json`;
  если системный запуск Chromium не удался, тест берёт бинарник из `CHROMIUM_PATH`;
  системные библиотеки Chromium ставятся от root: `npx playwright install-deps chromium`).
  Без браузера тест завершается кодом 2 с текстом обеих ошибок запуска — это не «прошёл».
  После деплоя можно проверить и живую страницу:
  `node tools/check.js https://samush.github.io/pulse3d/`.

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | разметка, стили, панель UI; подключает три скрипта ниже |
| `plan.js` | `const PLAN` — вся геометрия квартиры (см. `docs/GEOMETRY.md`) |
| `app.js` | код сцены: рендер, план/прогулка, отделка, мебель по слоям, панорамы `VIEWS` |
| `items.js` | мебель как данные: `ITEMS` (id, тип, помещение, слой, `pos`, `rot`, `size`, `fixed`), детали в локальных координатах; `setItemPose(id,pos,rot)`, `itemCorners(id)` |
| `layout.js` | режим «Расстановка»: выбор предмета в плане, перенос/поворот, варианты расстановки (`window.LAY`), предупреждения |
| `materials.js` | библиотека материалов `MATERIALS` (размер рисунка в метрах, шероховатость, рельеф) и режим «Визуализация» (`window.VIZ`): PBR-двойники |
| `lighting.js` | световые схемы (`window.LIGHTING`): нейтральный свет (hemi + sun с тенями), environment, единый пайплайн sRGB/ACES/exposure для 3D |
| `markup.js` | режим «Разметка» в плане: точка/отрезок/прямоугольник, карточка метки, «Скопировать для агента» (`window.MK`) |
| `three.min.js` | впендоренный three.js — не редактировать |
| `GLTFLoader.js` | загрузчик GLB из three.js r128 (`examples/js/loaders`), глобальный `THREE.GLTFLoader` — не редактировать |
| `APARTMENT.md` | спецификация помещений по БТИ — эталон номеров/площадей |
| `tools/plan.py` | работа с геометрией: `areas`, `check`, `remap` (сдвиг граней стен вместе с окнами/дверями/проёмами), `selftest` |
| `tools/check.js` | smoke-тест на Playwright + скриншоты в `tools/out/` |
| `deploy/angie.conf` | конфиг веб-сервера для альтернативного самостоятельного хостинга |

Внешних зависимостей у страницы нет (кроме необязательного гугл-шрифта) —
работает и с `file://`, и на Pages.

## Предметы (`items.js`)

- Каждый предмет — группа с постоянным `id` (`sofa`, `table`, `chair1…6`, `kitchen`, `wardrobe`, `kidbed`…):
  `pos` — северо-западный угол при `rot=0`, `size=[w,h,d]`, `rot` — градусы по часовой (вид сверху),
  `fixed:'wall'` — настенный/пристенный предмет, `attach:'table'` — стулья едут за переносом стола
  (за поворотом — нет, контракт не решён). Детали строятся в локальных координатах — переставить предмет значит
  поменять `pos`/`rot` (`setItemPose`), а не координаты каждой детали.
- `setItemPose` — единственная операция позы: двигает группу, пересобирает физику и зовёт `POSE_HOOKS`
  (разметка перепроверяет привязки меток, расстановка обновляет выделение). Не двигать группы напрямую.
- `glb:'models/<id>.glb'` — модель предмета: сначала строится процедурный `build` (fallback и proxy), затем `loadItemGlb`
  грузит GLB и на успехе заменяет им процедурные меши; при ошибке (`file://`, сеть) предмет остаётся процедурным, запись в `VIZ.loadErrors`.
  При загрузке `validateItemGlb` пишет console-warning (не исключение): единицы не метры, `Box3` вне `size` ±1 см, низ не на уровне процедурной версии (подвесные висят), спинка не с той стороны, что у процедурной (`glbFacade:false` отключает для симметричного верха).
  Имена материалов в GLB — слоты (`fabric`, `wood`, `paint`, `metal`), покрытия (`upholstery`, `cushion`, `piping`, `cover`; таблица `GLB_MATS`) или ключи `ITEM_MATS` (`kmat`, `pillow`…): модель получает серые материалы концепта с этим слотом/оттенком, исходное имя остаётся в `mesh.userData.glbMat`.
  UV моделей в метрах без швов на скруглениях (`tools/models/glb.js`); `node tools/models/uvcheck.js` — доля растянутых треугольников, `node tools/uvshot.js` — checker-кадры в `tools/out/uv-*.png`.
  Один файл на несколько предметов кэшируется и клонируется с общей geometry; `glbRot` (градусы по часовой, как `rot`) поворачивает модель внутри группы вокруг центра footprint.
  Модели генерируются скриптами `tools/models/*.js` (node + `three.min.js`), см. `models/README.md`.
- Материалы деталей (`ITEM_MATS`) несут `userData.slot` — физический класс для визуализации
  (`chrome`, `metal`, `glass`, `fabric`, `emitter`, `screen`, `wood`, `cabinetPaint`; остальное — `furniture`), параметры в `MATERIALS[slot]`. UV боксов `b()` — в метрах.
  Helper'ы деталей в `buildItem`: `b.round` (бокс с фаской), `b.rrect` (скруглённый прямоугольник-`Shape`), `b.plate` (рамка розетки/выключателя, сама объявляет proxy), `b.spot`, `b.led`, `b.handle` — описание в `tasks/realism-all/PLAN.md` §3.
  Серый цвет концепта от слота не зависит.
- `SCENE_REV` — fingerprint геометрии и каталога (PLAN + id/size предметов); пишется в экспорт разметки
  и вариантов, при несовпадении загрузка сообщает об этом, но применяет данные. Несовпадение `PLAN.meta.version`
  для вариантов — конфликт, документ не применяется.
- Задача от пользователя приходит через разметку: «поставь комод в M3» — метка M3 даёт координаты
  опорной точки, размеры и поворот в той же конвенции, что и предметы; в тексте метки перечислены
  предметы, чей контур она пересекает.

## Материалы и свет (галочка «Материалы», селектор «Свет»)

- **План** (вид «Сверху») — простые материалы без света, контуры и размеры. Любой 3D-вид (прогулка, панорамы) — освещённый:
  `MeshStandardMaterial`, тени, ACES tone mapping, sRGB, exposure 0.75 — один пайплайн для всех 3D-комбинаций (`lighting.js`).
- **Материалы** (`VIZ.set`, `localStorage['pulse3d.viz']`): включены — PBR-двойники с картами цвета, шероховатости и микрорельефа;
  выключены — нейтральные серые Standard-двойники без карт (проверка формы), прозрачность стекла/тюля сохраняется.
- **Свет** (`LIGHTING.set`, `localStorage['pulse3d.light']`): `neutral` — фиксированный hemi + sun с тенями (2048), без источника за камерой;
  `lamps` — светильники квартиры: каталог `LIGHTS` (`lighting.js`, координаты из `tasks/materials-lighting/lighting-plan.md`), источник и target лежат в группе предмета и едут за `setItemPose`; группа включения `LIGHTING.group('g4.sofa', false)` гасит intensity своих источников и emissive своих рассеивателей (`ITEM_MATS.led` клонируется по группам); sun выключен, hemi 0.15 — явное заполнение, своя PMREM без окна. Смена света не трогает материалы и наоборот; `syncMode` применяет обе настройки.
- Описания материалов — в `MATERIALS` (`materials.js`): размер рисунка в метрах задаёт `repeat`
  текстур (UV везде в метрах, поэтому плитка 0.6 м одинакова на полу и стенах), `rough`, `bump`.
  Карты шероховатости и нормалей строятся процедурно из канваса цвета; внешнюю картинку можно
  подключить полем `image` — при ошибке загрузки остаётся процедурная, ошибки в `VIZ.loadErrors`.
- Покрытия (`COATINGS`, `materials.js`): наборы из `textures/<ключ>/` (см. `textures/MANIFEST.md`), класс + размер в метрах + поворот + цвет.
  Назначение: `VIZ.coat(id, ключ ITEM_MATS | слот | '*', покрытие|null)` на предмет (или поле `coat:{fabric:'sofaWeave'}` в `ITEMS`),
  `VIZ.coatFinish('board'|'wall'|'facade'|'ceiling'|ключ finishMats, покрытие)` на отделку. Двойник кэшируется по (исходный материал, покрытие),
  текстура — по (файл, размер, поворот): одинаковое покрытие у шести стульев — один материал. Без назначения двойник остаётся серым концептом.
- Зеркала (слот `mirror`): явный `envMap` из `VIZ.mirrorEnv()` — своя PMREM-карта без окна, не `scene.environment`; яркость по схеме света `VIZ.mirrorEnvIntensity`. Подсветка `bathmirror` — `ITEM_MATS.mirrorLed`, свой emitter для группы `g9.mirror`.
- Поздний GLB получает текущие материалы через `VIZ.adopt`. В headless-прогоне (software GL) прогулка ~5–6 кадров/с в любом режиме.

## Столкновения в прогулке

Стены, окна и мебель непроходимы всегда: у предмета есть невидимые боксы в `physGroup` (`items.js`),
лучи движения идут на высотах 0.25/0.5/1.4 м. Боксы либо объявлены явно в `build` через
`b.phys(x0,x1,y0,y1,z0,z1)` (диван, кровать-чердак, ванна — детализация меша не меняет физику и проходы),
либо, если объявлений нет, берутся по одному на каждый меш. Скрытие слоя мебели физику не меняет;
перенос предмета или смена варианта пересобирает боксы.

## Расстановка (кнопка «Расстановка» в плане)

- Клик по предмету — карточка: x/z опорной точки, поворот (шаг 90°), «Перенести» кликом по новому
  месту (с привязками разметки), Ctrl+Z. Стулья едут за столом (`attach`), пристенные предметы
  (`fixed:'wall'`) двигаются только вдоль своей стены и не вращаются.
- Предупреждения (не запрет): выход за границы помещения, пересечение с другим предметом
  (по боксам деталей из `physGroup`: диванчик между ножками кровати-чердака и розетка над столом не пересекаются),
  проход уже 0.7 м — только между напольными предметами, по деталям и только там, где детали стоят друг напротив друга (диагональ углов — не проход). Подвесные (низ выше 1.9 м) и плоские (ковёр, верх ниже 0.02) не мешают никому.
- Варианты: «Исходная» (из `items.js`, только чтение) и именованные копии — хранятся как позы
  предметов по ID в `localStorage['pulse3d.layout']`, переключаются селектором, «Сброс» возвращает
  исходные позы в варианте, «Текст» — расстановка для агента, «Экспорт/Импорт» — JSON с проверкой.
- Повреждённое или несовместимое сохранение (`pulse3d.layout`, `pulse3d.marks`) при загрузке не перезаписывается:
  строка остаётся, в подсказке — причина; при первом новом сохранении она переносится в ключ `*.bad`.
- Смена камеры (`controls.setPlan/setFPV/setPose`, пресеты `setView`) всегда зовёт `syncMode`: подсказки,
  выключение разметки/расстановки вне плана и `VIZ.apply` живут там, отдельных обработчиков кнопок нет.
  Пользовательский текст в карточки вставлять через `esc()`.

## Вид «Сверху»

Ортографическая камера: ЛКМ вращает (изометрия без искажения размеров), ПКМ/пробел/два пальца/✥ —
сдвиг, колесо/pinch/ползунок — масштаб. При включённой «Разметке» или «Расстановке» план ставится
строго вниз и ЛКМ сдвигает.

## Разметка (кнопка «Разметка» в плане)

Основной способ задать место объекту — метка на плане, а не адрес клетки:

- Точка (`1`), отрезок (`2`), прямоугольник (`3`, два противоположных угла); шаг сетки 1/5/10 см,
  привязка к стенам и углам ближе 15 см; `Esc` — отмена рисования/инструмента, `Delete` — удалить,
  `Ctrl+Z` — отменить последнее действие. Клик без инструмента выбирает метку.
- Карточка справа: ID (`M1`, `M2`…), название, помещение (или «пересекает границу»), координаты,
  размеры, поворот (по часовой вокруг опорной точки — северо-западного угла), фасад, высоты,
  расстояния до стен; всё редактируется числами; «Перенести» — клик по новому месту.
- «Скопировать для агента» даёт текст с точными координатами в метрах (план v2, origin, оси),
  старым адресом клетки, размерами, поворотом, высотами и шагом. Пользователь пишет:
  «поставь комод в M3, светлое дерево» — агент берёт числа из текста. Без clipboard текст
  выделяется в поле для ручного копирования.
- Привязки: при клике ближе 15 см к краю предмета точка прилипает к нему, метка запоминает `bind`
  (ID предмета и сторона) и пишет это в текст. Для точки есть режим «на стене»: стена комнаты,
  угол отсчёта, расстояние вдоль стены и высота **центра** — всё редактируется в карточке.
- Сохранение: метки лежат в `localStorage` (`pulse3d.marks`, формат 1, версия плана) и
  восстанавливаются при открытии; «Экспорт» скачивает JSON, «Импорт» читает файл с проверкой
  формата — битый файл отклоняется, текущие метки остаются. Если план другой версии или предмет
  с привязкой сдвинулся/исчез, метка не переносится, а помечается конфликтом в карточке и статусе.

## Сетка-адресация (галочка «Сетка-адресация»)

Пользователь задаёт положение объектов адресами клеток, а не метрами:

- Метровые клетки пола: буквы A,B,C… с запада на восток, цифры 1,2,3… с севера
  на юг, от фиксированного `PLAN.meta.origin` (угол A1; изменение контура адреса не меняет).
  Подпись — в северо-западном углу клетки. Адрес на границе клеток — у клетки восточнее/южнее.
- Точнее — дециметры внутри клетки: `D7+26` = от угла клетки D7 два дм на восток,
  шесть на юг. Пересчёт: x = minX + 3×1 + 0.2; z = minZ + 6×1 + 0.6.
- Высота: H в дециметрах от чистового пола, H0–H27 (потолок 2,7 м). В сцене чистовой пол — `y=0`, см. `docs/GEOMETRY.md` («Высоты»).
- Объект описывается кубом: «от C2+00 до стены на север, глубина 6 дм, H0–H9».

## Правила правок геометрии

1. Геометрию не править руками: грани стен совпадают по координатам в
   `rooms[].poly`, `slabs`, `cells` — двигать только через
   `python3 tools/plan.py remap …` (инвариант описан в `docs/GEOMETRY.md`).
2. `rooms[].area` — площади БТИ, менять только если реально меняется
   планировка; при расхождении полигона и БТИ эталон — БТИ (`APARTMENT.md`).
3. После правок: `python3 tools/plan.py check` (согласованность и площади) и
   `node tools/check.js` (сцена грузится, высоты, скриншоты глазами).
4. Проёмы, окна, двери и контуры санузлов живут в `PLAN` (`doors`, `windows`, `openings`,
   `baths`), не в `app.js` — тогда `remap` двигает их вместе со стеной.
5. `tools/out/` — артефакты проверки, в git не коммитятся.

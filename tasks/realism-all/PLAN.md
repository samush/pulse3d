# Реализм всех предметов сцены: GLB-модели и детальная процедурная геометрия

Дата: 2026-09-06, база `8b81344` (после `tasks/realism-living`, PR #3–#10). Статус этапов — в §2.
Образец результата: диван, стулья и стол кухни-гостиной 4 (`tasks/realism-living/PLAN.md`, там же §10 с цифрами).

## 0. Цель и принципы

- Каждый предмет `ITEMS` должен читаться как собранный из реальных деталей: толщины, фаски, зазоры фасадов, ручки,
  ножки, мягкие подушки со скруглением. Палитра остаётся серой; различие материалов — через слоты (§4).
- **Мягкие и сложные формы — GLB** (`models/<id>.glb`, генератор `tools/models/<id>.js`). **Параметрические
  корпуса и мелочь — процедурно** в `items.js` через `b()` и `THREE.*Geometry`. Правило выбора: если форма описывается
  боксами, цилиндрами и extrude с фаской — процедурно; если нужны скругления ≥ 15 мм на многих рёбрах, купол, кант,
  складки, lathe-профиль — GLB.
- Инварианты (не менять): `id`, `pos`, `rot`, `size`, опорная точка (СЗ угол), `fixed`, `attach`, `SCENE_REV`,
  проходы и предупреждения `LAY`, разметка. Все детали внутри `size` (тест `Box3 ≤ size + 1 мм` для процедурных,
  `validateItemGlb` для GLB). Не масштабировать модель «под кадр», не добавлять декор и предметы, не менять палитру,
  не трогать `three.min.js`/`GLTFLoader.js`.
- **Сначала proxy, потом детали.** У предмета без явных `b.phys` физика берётся по одному боксу на меш; любая
  детализация сдвинула бы столкновения и предупреждения расстановки. Перед детализацией объявить `b.phys(...)`,
  повторяющие сегодняшние AABB мешей (как §2 в `tasks/realism-living/PLAN.md`), и зафиксировать число боксов
  тестом. Исключение: настенная мелочь без влияния на проходы (розетки, выключатели, споты, LED) — один `b.phys`
  на предмет, равный текущему габариту.

## 1. Что уже есть (использовать, не переписывать)

| Что | Где | Как |
|---|---|---|
| Загрузка GLB | `items.js`: `glb:'models/x.glb'`, `glbRot`, `loadItemGlb`, `GLB_CACHE` | процедурный `build` остаётся fallback и proxy; модель подменяет меши после `DOMContentLoaded`; один файл на несколько предметов кэшируется и клонируется (общая geometry) |
| Валидация | `validateItemGlb` | warning в консоли: единицы, `Box3` в `size` ±1 см, низ на y=0, pivot СЗ, фасад как у процедурной версии (центроид верхней четверти) |
| Материалы GLB | `GLB_MATS` в `items.js` | имя материала в GLB = слот (§4), подменяется серым материалом концепта |
| Генератор | `tools/models/glb.js` | `rbox(w,h,d,r,x0,y0,z0,{m,step,crown,fold})` скруглённый бокс; `piping(x0,z0,w,d,r,y,radius)` кант по скруглённому прямоугольнику; `cylinder(cx,y0,cz,r,h,seg)`; `toGlb(parts)` → `{buf,triangles}`, parts=`[{geo,mat:'fabric'}]`, один индексированный меш на материал, UV в метрах. Любая `THREE.*Geometry` из core (`ExtrudeGeometry`, `LatheGeometry`, `TubeGeometry`) годится как `geo` после `translate/rotate` в локальные координаты предмета |
| Примеры | `tools/models/sofa.js`, `tools/models/chair.js` | структура скрипта, комментарии, вывод в `models/` |
| Процедурно | `b(x0,x1,y0,y1,z0,z1,mat)` (UV в метрах), `b.phys`, `g.add(new THREE.Mesh(...))` для не-боксов | стол: `ExtrudeGeometry` с bevel, `CylinderGeometry(…,4).rotateY(π/4)` для квадратных конусных ножек |
| Тесты | `tools/check.js` | блоки «realism-living step N» — образцы: число боксов PHYS, загрузка GLB без warning, общая geometry, слоты |
| Снимки | `controls.setPose(px,py,pz,tx,ty,tz)`, `VIZ.set(bool)`, `renderer.info` | скрипт приёмки: `tasks/realism-living/PLAN.md` §10 (ракурсы), скриншоты в `tools/out/` (не в git) |

Blender на машинах нет; генераторы — node + `three.min.js`. Если появится CC0-модель (Poly Haven) с точным габаритом,
можно взять её: источник и лицензия в `models/README.md`.

## 3. Общие helper'ы (этап A, первый PR)

В `items.js` рядом с `b`:
- `b.plate(x0,x1,y0,y1,z0,z1,mat,{keys=1})` — настенная рамка розетки/выключателя: рамка с фаской 1 мм
  (`ExtrudeGeometry`), внутри клавиша/розетка на 2 мм ниже; ориентация по тонкой стороне `size`
  (0.01 по x или по z). Материал `plastic`. Один `b.phys` на габарит.
- `b.spot(cx,cz,r,mat)` — точечный светильник: кольцо (`TorusGeometry` или `LatheGeometry`) + диск `led`,
  утоплен в потолок y=2.70.
- `b.led(x0,x1,y0,y1,z0,z1)` — LED-лента: полоса `led` 8 мм + алюминиевый профиль `metal` вокруг.
- `b.round(x0,x1,y0,y1,z0,z1,r,mat)` — бокс с фаской r через `ExtrudeGeometry` (фасады, столешницы, полки);
  UV в метрах даёт `ExtrudeGeometry` сам.
Ручки: `b.handle(cx,cy,cz,len,axis)` — скоба Ø8 мм из `TubeGeometry`/`CylinderGeometry`, слот `chrome`.

## 4. Слоты материалов

Существующие: `chrome`, `metal`, `glass`, `fabric`, `emitter` (`led`), `screen`, `wood` (столы), `paint` (каркасы),
`furniture` (по умолчанию). Этап A добавляет в `MATERIALS`, `SLOTS`/`ITEM_MATS` и `GLB_MATS`:
`plastic` (rough 0.4 — рамки розеток, корпуса ламп), `ceramic` (rough 0.12 — сантехника), `acrylic` (rough 0.2 — ванна),
`leather` (rough 0.6 — изголовье, пуфы), `mirror` (rough 0.05, без metal — без environment map металл рендерится чёрным; отражение придёт с G3). Другие этапы новые слоты **не добавляют**,
чтобы не конфликтовать; если чего-то не хватает — берут ближайший и пишут в TODO этого файла.

## 5. Бюджеты и стоимость

Треугольники на предмет: крупный мягкий (кровать, диван) ≤ 12k; кресло/стул/пуф ≤ 3k; сантехника ≤ 4k; корпусная
мебель процедурно ≤ 1k; мелочь ≤ 200. Сцена сейчас ~23k в самом тяжёлом ракурсе; после всех этапов допустимо
≤ 120k. Draw calls: GLB — один меш на материал; процедурно — не дробить фасады на десятки мешей без нужды.
Один файл на повторяющиеся предметы (кресла, унитазы, споты — споты процедурно через helper).

## 6. Порядок работы в этапе

1. Прочитать `CLAUDE.md`, `tasks/realism-living/PLAN.md` (§0–§5, §10), этот файл, свою строку в §7–§12.
2. Снять «до»: ракурсы этапа (§7–§12, `setPose`) в концепте и VIZ, `renderer.info` — в `tools/out/before-*`.
3. PR 1: proxy для всех предметов этапа + тест числа боксов + статус этапа `in-progress`. Ноль визуальных изменений.
4. PR 2…N: по одному-трём предметам (GLB — генератор + модель + `glb:` + тест загрузки без warning; процедурно —
   код + тест «детали внутри size»). После каждого PR `node tools/check.js` зелёный.
5. Последний PR: «после» в тех же ракурсах, таблица результатов в §13 (треугольники/calls/p95 до → после, отклонения),
   статус `done`, `node tools/check.js https://samush.github.io/pulse3d/` после деплоя.
Отчёт в чат после каждого PR: что сделано, номер PR, что дальше.
